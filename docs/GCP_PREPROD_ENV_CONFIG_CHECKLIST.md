# GCP preprod operator checklist

**Status (1 October 2026): no remote preprod acceptance is recorded.** The earlier checklist claimed a GCS evidence vault and HMAC keys. That configuration is retired; it does not meet the repository's S3 Object Lock Compliance requirement. Use the [current deployment guide](GCP_PREPROD_DEPLOYMENT_GUIDE.md) and [private environment template](../infra/docker/environments/.env.preprod.example).

- [ ] Confirm the authorized GCP project ID and number, `asia-south1` workload region, billing, IAM and deployment principal. Read back an access-controlled, encrypted regional GCS bucket for **Terraform state only**; set `AXIOM_TF_STATE_BUCKET`. No local Terraform state may be present.
- [ ] Approve an AWS S3 bucket in `ap-south-1` with native Object Lock enabled, default **COMPLIANCE** retention of at least seven years, and bucket-scoped application credentials. Create a nonempty synthetic probe, preserve its exact version ID, and read back that version's Compliance retention date. Set `AXIOM_EVIDENCE_BUCKET`, `AXIOM_STORAGE_ENDPOINT=https://s3.ap-south-1.amazonaws.com`, scoped access/secret, and probe key/version in the private environment file. GCS Bucket Lock is not an equivalent evidence provider.
- [ ] Provision/review regional Cloud SQL, GoTrue/PostgREST signing keys minted as one set, Redis, Temporal, model-provider DPAs, email provider, MFA and approval signing keys, and Cloud Run identities. No real client values may leave `ap-south-1` through a model provider.
- [ ] Select a reviewed clean commit. Set `AXIOM_RELEASE_SHA` to its full SHA, approve pinned GoTrue/PostgREST upstream image digests, build all nine images under `release-<SHA>`, and retain the private registry digest manifest. Verify every digest resolves in the expected Artifact Registry project and region.
- [ ] Run the strict preflight and Terraform dry run using `./scripts/deploy-preprod-gcp.sh --env-file <private-env-file> --dry-run`; review exact plan, secrets, state backend, migration order, rollback and traffic strategy before an actual deploy.
- [ ] Deploy the same SHA, read back Cloud Run image digests and reported release identity, verify database migration ledger and S3 exact-version proof, then execute `./scripts/run-deployed-acceptance.sh <private-target-json> api-only` and the full browser acceptance. Archive sanitized evidence, failures, operator decision and timings. Do not substitute local Docker output for this gate.
