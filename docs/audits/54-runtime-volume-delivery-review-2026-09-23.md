# Review 54 — protected host-to-container runtime volumes

Review found the native node writes its Workload API under `/run/workload`, while the isolated launcher accepts a named `axiom-workload-api-*` Docker volume. Name availability alone does not establish the intended host-directory mapping. The new protected root helper binds fixed local-driver options, source paths and deterministic names to the reviewed host manifest and state UUID. It requires initialized state, reviewed active services and current exact-node health, checks all conflicts before mutation, writes a protected record before creation and refuses repair/deletion. An existing active mount must match the source device/inode and required read-only mount flags. Identical explicit retries are supported after inspection; neither preparation nor read-only checking starts a container.

The native acceptance extension uses an unprivileged Docker consumer with only read-only workload and health directory volumes. It verifies actual node + image-config digest + UID admission, wrong UID/image refusal, continued access through socket replacement and visibility of atomic health updates. It preserves prior node/observer lifecycle checks. The deliberate observer rate-limit test now resets its own budget before three explicit starts, avoiding dependence on container-build duration. Production limits remain unchanged.

Validation at source preparation: 117 deployment tests. Local Docker delivery and expanded native acceptance are recorded separately; no native success is inferred from unit tests. The fixture substitutes local join-token identity and does not prove GCP attestation, full controller launch or cloud IAM. The standard local Docker data root is required; alternative roots are not silently accepted.

[Docker's volume documentation](https://docs.docker.com/engine/storage/volumes/) specifies read-only mounts and `volume-nocopy`. The helper and native consumer make those choices explicit so image contents cannot populate the host runtime directories. No executable bind mount or admin/daemon socket is delivered to workers. Full controller container packaging/admission/supervision and scoped TLS/IAM/KMS delivery follow next. No application authorization or schema contract changes.

Additional review caught a namespace-observation gap: a private Docker mount namespace could hide active mounts from the host checker. The helper now requires the root-owned daemon to share the caller’s mount namespace before Docker operations. Unsupported namespace layouts fail closed rather than being reported as unmounted. Run this host preflight outside a separate filesystem namespace.
