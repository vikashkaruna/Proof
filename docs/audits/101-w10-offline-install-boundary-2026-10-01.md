# W10 offline install boundary — 1 October 2026

This is a **local engineering checkpoint**, not W10 closure or deployed on-prem acceptance. No shared Docker target or cloud resource was touched. The on-prem Compose topology is internal-network-only and pins every image by digest; `bootstrap-onprem.sh` validates an operator-owned 0600 environment, signed offline license and local image inventory before startup. The BFF, agent runtime, model gateway and Temporal worker have request-time or periodic license guards. A configured local model endpoint is in-network; absent configuration returns an explicit unavailable state. MinIO initialization checks a seven-year Compliance default, but no real exact-version retention readback is recorded here.

The checkpoint removes the service-role JWT from the web container and sets `pull_policy: never` on all 14 on-prem services. It narrows preflight URL and CORS inputs to explicit intranet origins, and checks that self-hosted anon/service JWTs use HS256 and are currently valid. First-install bootstrap now refuses any existing appliance container or persistent state volume. It cannot be used as an unreviewed upgrade or restore against a live database. Focused preflight and bootstrap refusal tests cover these boundaries.

**Still open for W10:** approved pinned images for all services and WORM server/client, a valid signed offline license, an isolated appliance with egress blocked, protected operator secrets, a verified exact retained WORM object/version and server configuration, a reviewed backup set covering PostgreSQL and evidence objects, a safe upgrade/rollback procedure with migration review, a complete restore with integrity/RPO/RTO evidence, and real strict Auth/PostgREST/MFA multi-persona API/browser acceptance. The existing `scripts/test-backup-restore.sh` targets a different local Supabase database by default and excludes evidence objects/RPO; it cannot be treated as on-prem recovery proof. An empty or partial first install must be recovered under an explicit operator procedure; rerunning bootstrap is intentionally refused. Neither a passing local unit suite nor Compose rendering proves those live gates.

See [Doc 16](../16_Operator_Completion_Runbook.md) and [Doc 18](../18_Operator_Deploy_And_Acceptance.md) for the release conditions. The literal S3 Object Lock Compliance requirement remains binding; an unverified emulation or bucket policy is not release evidence.
