# Review 50 — persistent SPIRE state admission

The pinned [agent disk key manager](https://github.com/spiffe/spire/blob/v1.15.3/pkg/agent/plugin/keymanager/disk/disk.go) and [issuer disk key manager](https://github.com/spiffe/spire/blob/v1.15.3/pkg/server/plugin/keymanager/disk/disk.go) treat a missing key file as an empty store. Automatic startup must therefore distinguish initial provisioning from unintended key loss before launching either process.

Revision 61 adds an offline owner-only state binding preparer and read-only Linux/root gate. It binds role, UUID and domain/node configuration; probes the actual superblock UUID; checks the fixed Terraform device alias against the mounted device; rejects root-backed, subtree, nested, stacked, unsafe or absent mounts; and requires protected canonical ancestry. The [Linux mountinfo contract](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html) supplies device, root, mountpoint and mount/superblock options. Device and mount identity are checked again after state reads. Root-controlled configuration, binaries and device topology remain trusted. This is a startup check, not continuous disk monitoring or protection against a malicious root.

Ready checks require the exact private marker and structural issuer key/SQLite state or node key/recovery state, including nonempty encoded key/certificate records. [SPIRE agent storage](https://github.com/spiffe/spire/blob/v1.15.3/pkg/agent/storage/storage.go) defines the recovery cache. Reads reject symlinks, hardlinks, nonregular or oversized/private-permission violations, and duplicate JSON fields. Cryptographic validity, actual node identity and registry semantics remain SPIRE/application obligations; the guard does not replace them. Missing state never triggers creation, repair or reenrollment. The distinct empty check only verifies a blank bound filesystem; it does not mutate or authorize normal startup.

Validation includes 20 new tests (58 deployment tests total) covering mount/device and role substitution, filesystem UUID mismatch, mount changes during the check, wrong permissions, file aliases, FIFO refusal, empty/missing/foreign keys and recovery records, and preparer no-overwrite behavior. Three new real local SPIRE outcomes validate actual private issuer/node files and reject an empty node volume before the agent starts, preserving the earlier 21 outcomes. The real test caught a format assumption: node certificates are base64-encoded PEM, unlike the key file's base64-encoded DER. The guard and negative fixtures now distinguish them. Test volumes also have explicit owner-only initialization and SPIRE starts with umask 077. No real host device is mounted or formatted by these tests. Full GCP mount-loss/supervisor and first-enrollment acceptance remain open. Exact merge CI results are saved in the session.

Remaining deployment work: checksum-pinned installation, reviewed initial provisioning/marker delivery, service and mount supervision, CA distribution, scoped IAM/KMS, TLS, full production controller/worker startup, Mumbai backup/restore and the opaque scheduler. No resources were provisioned and no live key or database state was modified. Full roadmap completion is not claimed.
