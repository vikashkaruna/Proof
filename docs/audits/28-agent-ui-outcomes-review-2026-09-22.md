All four invocation surfaces now use a shared client response contract. Requests contain JSON and a fresh correlation ID; HTTP errors, wrong agent/correlation, missing/failed status, contradictory success and invalid receipt metadata cannot create success state. The helper sanitizes network/JSON errors and accepts a bounded public BFF error message. It does not grant authority, compute scores or execute business rules.

Assessment awaits the response, marks only the invoked Parikshan stage complete, and reads score/count/exposure values directly from refreshed server props. A useRef lock prevents duplicate clicks before React renders the running state. There is no timer-driven scoring or fabricated completion of discovery, classification, sealing or reporting. Runtime receipt links are labelled ledger entries; active indicators use teal rather than gold reserved for sealed evidence.
