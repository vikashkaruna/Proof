# Revision 120 — source-bound Pramaan board dossier (2026-10-01)

## Scope and claim boundary

This is a **partial W8.4 milestone**. Only `board_executive` has an authoritative source contract: a published board report generated from a finalized assessment, its frozen board request/source packet, and exact independently retained source JSON and PDF versions. The dossier service reads and verifies those provider versions, binds the source packet's `request_id` to the selected report's `board_report_requests` row, and builds a bounded ZIP with the exact source and PDF bytes plus a limited claim manifest. A manager may prepare it; a current internal founder seals it after Compliance-lock receipt verification. A pending or uncertain provider result cannot be sealed, and an explicit missing-object retry must reproduce the original bytes. The input title is normalized once before the manifest and database write so an ambiguous-write retry remains byte-identical.

`dpb_statutory`, `auditor_assurance`, `technical_register`, and `full_closure` still return `source_bound_dossier_required`; outbound email dispatch remains closed with `source_bound_dispatch_required`. Historical dossiers remain unverified and cannot enter the source-bound seal path. No production provider or statutory submission is claimed.

## Security-head finding and remediation

A review after the earlier PR-head acceptance found that shared `service_role` credentials, also present in agent/worker contexts, could invoke founder-review, release, board/evidence-pack and Pramaan archive RPCs with caller-supplied actor IDs or provider receipts. This could create false human approval or retained-proof claims even though normal BFF routes enforce checks. The amended, unmerged 0089 migration revokes those mutation privileges from `service_role` and grants narrowly enumerated RPC EXECUTE to a `statutory_proof_writer` role (`NOLOGIN`, `NOINHERIT`, `NOBYPASSRLS`) assumable only by PostgREST `authenticator`. The BFF alone receives a separately signed role JWT; services refuse mutations when the writer client is unavailable. Older synthetic report-draft seed calls were removed, and obsolete direct draft/PDF entry points were revoked.

The direct SQL boundary test uses a real founder fixture and checks that generic `service_role` cannot prepare a pack, forge review/release, start a retained build, settle a Pramaan claim or insert a statutory artifact. The scoped writer can invoke the reviewed path, while the source-bound dossier guard still refuses absent source. A disposable PostgREST v16.1 HTTP probe returned `403 permission denied for function review_report` for a signed `service_role` JWT and HTTP 200 with a founder-authority business refusal for the signed scoped writer JWT. That is gateway role separation, not a positive retained-provider journey. The complete amended-head CI, provider/browser and exact-staging gates must pass before this security finding is marked closed; no remote preproduction or production claim follows from local tests.

The amended 0000–0089 disposable database run passed all SQL security suites, the evidence-pack contention race, populated upgrades and TCP migration history checks (`/tmp/axiom-statutory-full-db-final.log`). Full workspace tests passed 16/16 tasks (including 1,474 BFF tests; 10 existing live connector skips), typecheck and lint passed 16/16 each, build passed 4/4, formatting passed and the local security scan reported no known vulnerabilities (`/tmp/axiom-writer-final-{tests,typecheck,lint,build,format,security}.log`). These local results do not include the amended-head real provider/browser journey or source CI.

This repair is limited to the board/statutory/Pramaan/evidence-pack proof RPCs. A broader direct-`service_role` audit identified older human or provider assertion paths in policy review (0076), consent lifecycle (0069/0072), evidence ingestion (0073), monitoring alerts (0078), and 0035/0055. Those need a separate restricted-writer remediation and negative/positive gateway validation before any whole-product security or production clearance.
