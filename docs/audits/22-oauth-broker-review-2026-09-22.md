# W4.2 OAuth broker core review — 22 September 2026

Reviewed staging `9a75743` with successful CI 35659326878; no newer other-model implementation was present. This continues the green vault milestone without calling the wider W3/W4 goal complete.

The broker opens only context-bound encrypted profiles after a trusted authorization dependency accepts the workload and scope. Its production default denies every request. There is no acquisition route and no role/shared-token bypass. W4.3/4 must supply the real authority implementation; current authority test doubles are explicitly fixtures.

The implemented OAuth handlers distinguish client authentication from authorization grants. Client JWT assertions identify the registered OAuth client; JWT bearer grant issuer/subject/audience are configured separately. Neither forwards an internal SVID as a client assertion. RSA/EC signatures, short assertion lifetime, fresh identifiers, exact requested scope sets, bearer response shape, cache directives and token lifetime are tested against isolated authorization servers. The pinned HTTPS transport verifies the original hostname/CA, avoids DNS rebinding and redirects, blocks metadata pins and bounds time/bytes.

Review fixes included accounting for response latency in external expiry limits, strict OAuth profile validation before vault provisioning, immutable copies of request/lease/configuration, generic failures, best-effort byte cleanup, synchronous transport cleanup and repeated revocation checks before release. Ledger failure withholds the token. A failed post-exchange check can leave an external token valid at its issuer even though Axiom destroys/withholds its local handle; controlled transports must recheck current authority per invocation. No distributed atomicity with the external issuer is claimed.

Migration 0040 adds a service-only snapshot read that repeats tenant/estate/connector/credential context, descriptor and optimistic version checks, live parents and expiry/revocation. It does not replace workload authentication or authorize grants. New audit actions use append_ledger exclusively. Existing service-role database access remains a trusted backend boundary, not proof of workload credential isolation.

Validation: 471 BFF tests including 107 broker tests; 41 migration files, ten existing concurrency suites and upgrade regressions passed locally. TLS tests include real encrypted-profile → broker → local HTTPS AS acquisition with synthetic authority/KMS; SQL and PostgREST-client adapter tests exercise separate boundaries. No real cloud KMS, SPIRE deployment, client token endpoint or client action was used. Workspace/container/exact merge acceptance is recorded in the handoff after completion.
