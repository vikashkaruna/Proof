# W8.3 DPB recorded-source review pack — 2026-10-01

The DPB format now has a narrowly supported source: a recorded breach and a DPB notification reviewed by a second human. Request creation freezes the exact database fields and their SHA-256 in an immutable tenant-scoped source row. A notification must be reviewed or recorded as sent, must belong to the same breach and tenant, and cannot be superseded. The pack states that breach facts are operator records and that a recorded delivery outcome does not establish regulator receipt or acceptance. It is a review pack, not a filed statutory form, forensic finding, legal opinion or independent attestation.

The requester-supplied title is an internal reference and is not printed in the retained PDF. Its document heading is fixed as “Recorded DPB notification review pack”, preventing a title from being used as an unsupported filing or acceptance claim.

Only an owner, admin or internal founder can request a source. Only an internal founder can create the deterministic draft, review its exact content digest, build retained artifacts or release. The browser exposes the frozen source and exact draft manifest to that founder, verifies both SHA-256 digests, and requires an explicit review confirmation. The source and draft are immutable; the build stores separately versioned source JSON and reviewed PDF under S3 Object Lock Compliance mode. The database release function requires the approved content hash, both settled exact artifact versions and the PDF hash. The BFF re-verifies the provider's version and bytes before release and download. The generic statutory HTML/PDF renderer refuses DPB rows so it cannot create an unretained alternate copy.

The generic `release_report` RPC is wrapped after preserving its previous body under a private, ungranted function name. It refuses DPB rows even after artifact settlement, so provider readback and request-status bookkeeping cannot be skipped; all other report kinds delegate to the previous behavior. A row-level trigger independently rejects DPB publication without exact settled versions.

Migrations `0091` and `0092` are additive; applied historical migrations are unchanged. They enforce tenant keys, RLS, no direct service-role inserts, append-only ledger events, idempotency and a generic publication trigger for DPB builder rows. `tests/database/dpb-source-bound.test.sql` exercises source refusal and freeze, founder review, build settlement and release refusal/success. The focused report-kit and BFF tests exercise strict source binding, route authorization and provider refusal before unauthorized access. Browser surface: `/breaches/dpb-reviews`.

The request list batches report, build and PDF metadata reads for up to 50 visible requests; the browser does not issue one artifact-status call per row. Unreleased PDF hashes and build operation keys are visible only to the internal founder. A tenant owner or admin sees only their own requests.

Known proof boundary: S3 retention and readback are enforced by the production provider adapter but the disposable database suite uses recorded receipt fixtures. A live provider E2E run with a real reviewed notification, Object Lock-enabled bucket and founder session remains an integration gate. This work does not assert DPB delivery, regulator acceptance, legal completeness, or production deployment.
