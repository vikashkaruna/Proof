## Findings and implementation

- **Orchestration lacked a private persisted-result path.** The versioned assessment workflow now passes only tenant/job IDs to a private controller activity and returns validated receipt metadata. The trusted producer validates before Temporal submission and derives a stable workflow ID. Execution reuse is refused after completion or cancellation; repeat scheduling returns the existing execution. Legacy workflow types and histories remain unchanged.
- **Retrying a launch after a lost response would be ambiguous.** The new workflow invokes launch once, then performs bounded confirmation-only reconciliation. Activities and the workflow itself do not retry execution. Reconciliation cannot claim or launch an unclaimed job. Tenant/job and observed run bindings are checked; contradictory receipts remain unconfirmed. A missing process-cleanup observation does not become success. Real timeout, cancellation, pending-worker restart and replay are exercised.
- **A late controller response could launch after disconnection.** Abort checks now guard claim-to-launch transition, and cancellation reaches the private channel. The Unix transport holds its active slot until the controller actually settles, even after responding to a deadline. An already in-flight database operation can still commit; later independent confirmation remains necessary.
- **The controller needed an explicit private transport boundary.** The local/on-prem Unix server requires an empty, owned private directory and protected ancestors, sets a restricted socket group and exposes only run/reconcile operations with strict size/time/response limits. The activity independently checks socket type, owner UID and permissions; it has no TCP, proxy or redirect fallback. No proof, SVID, assessment input or database credential enters this channel. The acceptance scheduler subprocess receives an environment allowlist rather than inherited host credentials.
- **Private scheduling must not accidentally poll legacy payloads.** Explicit socket/owner CLI options select only the new assessment queue. The default legacy mode is preserved separately. Worker connection failures are logged without raw exception/credential details. Namespace ACLs remain mandatory: a workflow cannot remove private data that an unauthorized generic producer already placed in history.

The roadmap scoping section also distinguishes declared scope strings from the implemented tenant/task-bound Parikshan authorization. Its earlier blanket statement that this context was inexpressible is superseded; remaining worker and connector enforcement stays open.
