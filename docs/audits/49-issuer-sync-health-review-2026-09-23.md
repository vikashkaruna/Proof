# Review 49 — bounded issuer synchronization health

Revision 59 demonstrated that an alive SPIRE node can serve cached identity while its issuer is offline. A freshly opened Workload API stream therefore did not establish upstream synchronization freshness. This milestone adds that missing check to the dedicated VM controller; the raw Workload API adapter retains its narrower transport role.

The root-only observer queries the fixed local admin `Debug.GetInfo` operation using the pinned agent CLI, a two-second deadline, bounded output and no private stderr forwarding. The [SPIRE 1.15.3 debug service](https://github.com/spiffe/spire/blob/v1.15.3/pkg/agent/api/debug/v1/service.go) caches its response for five seconds. Its reported last successful sync advances after the manager updates bundles, taint state and workload caches in [the synchronization implementation](https://github.com/spiffe/spire/blob/v1.15.3/pkg/agent/manager/sync.go). A live local probe verified the JSON contract and that this timestamp stopped advancing during issuer outage.

The observer binds the node leaf identity and certificate expiry, then atomically publishes a minimal root-owned metadata file. Failures replace success with denial; stopped publication ages out. Consumers receive a read-only directory mount, not node admin access. The metadata reader checks root ownership, parent/file write permissions, canonical paths, regular-file type and bounded size. Credential-file permissions are not relaxed. Trusted host/mount configuration, pinned binary integrity and a trustworthy clock remain deployment obligations.

The controller requires an exact node binding in the same trust domain. It caps authority at ten seconds after observation, thirty seconds after issuer synchronization and node certificate expiry. It rechecks across bundle I/O and retains the earliest deadline. Unknown/malformed/future/foreign/stale observations, invalid underlying trust and detected backward clocks fail closed. This is bounded synchronization evidence, not a promise of instantaneous fleet revocation or independent proof that the issuer itself is uncompromised.

Known unhealthy state cannot consume a new dispatch claim. Expiry after claim prevents launch without restoring one-time authority. Every scoped tool's identity validation uses the gated trust source. Independent reconciliation remains available to establish already persisted truth. Existing conservative unconfirmed/review behavior is preserved; there is no new retryable preflight response, automatic relaunch, claim reset or automatic resubmission after an outage. These distinctions are tested explicitly.

Validation: 976 BFF tests (24 new), 38 deployment tests (ten new), workspace lint/types/tests and acceptance TypeScript. Separate real SPIRE acceptance increases to 21 outcomes while preserving all 14 earlier outcomes. It tests the actual root-owned file and read-only mount, absent controller admin access, wrong node, unsafe permissions/malformed data, publisher/node expiry, issuer outage refusal despite a working cached Workload API, and recovery after fresh synchronization. The composed controller/worker fixture also consumes the actual observer's snapshot. A test fixture initially supplied an incomplete claimed-payload type; the type check caught it and the fixture now supplies a valid payload before container integration was rerun. Final exact-merge CI/artifacts are saved in the session.

Source completion does not mean deployment. Supervised pinned host installation, immutable state-disk mount/initialization guards, protected CA delivery, scoped IAM/KMS, TLS and full deployed controller/image-admission acceptance, Mumbai-only backup/restore and the opaque scheduler remain open. No cloud apply, schema migration, client mutation or WORM change occurred. Full W3/W4 and earlier remaining work are not marked complete.
