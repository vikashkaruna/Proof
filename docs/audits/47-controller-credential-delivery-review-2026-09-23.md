# Review 47 — controller credential delivery before image attestation

The next node/image-admission design review found that the [SPIRE 1.15.3 Docker workload attestor](https://github.com/spiffe/spire/blob/v1.15.3/doc/plugin_agent_workloadattestor_docker.md) can emit raw container environment entries as workload selectors. The Revision 56 service required a backend key in its environment. That combination would expose a credential to the issuer when the future attestor is enabled. The present acceptance uses Unix attestation; neither Revision 56 nor 57 enabled Docker attestation, so this is a prerequisite correction before deployment, not a demonstrated current leak.

## Change

The dedicated service requires a protected `backendServiceKeyFile` path and explicitly allows only minimal non-secret environment settings. It refuses inline backend keys, static AWS secret variables, legacy service credentials, loader injection and unreviewed settings. It reads the key directly into the backend client without assigning it to `process.env`. The ordinary public BFF remains unchanged. Provider identity file paths are canonicalized; protecting their ownership/contents remains a deployment obligation. No claim is made that arbitrary operator secrets deliberately hidden in an allowed non-secret field can be identified.

The backend key shares the established owner-only regular-file checks. A single trailing line terminator is allowed; malformed, oversized, non-ASCII and multi-line inputs fail with fixed text. The read buffer is cleared after parsing, with no promise to erase immutable strings or client-library memory. The schema/example and operator runbook now use the file contract, superseding the earlier environment instruction.

## Acceptance and limits

New unit tests verify actual file permissions/content, refusal of broad environments and invalid backend regions/transport, and provider file-path validation. The real composed-controller harness loads its backend key through the new protected-file helper and verifies that backend, wrapping and TLS private fixture values do not appear in Docker's recorded environment. Temporary private storage is a UID-owned tmpfs and is removed before worker execution. The same real trust, task, container, SQL and independent confirmation path then runs.

All **952 BFF tests** (22 new), workspace tests/lint/typecheck, acceptance TypeScript and security/control gates pass. Real local integration passes **61 identity / 62 worker / three protected-trust outcomes**, retaining all prior outcomes. The dedicated image also refuses default startup with fixed output. An initial acceptance import pulled in the executable entrypoint and failed its CommonJS/top-level-await transform; extracting the shared protected-file helper into a module without startup code fixed that harness issue. Final exact-merge results are recorded in the saved session. Existing schema/application behavior is preserved. Actual Docker image attestation, persistent issuer/node bootstrap, scoped IAM/KMS, health, recovery and opaque scheduler deployment remain open. No cloud resource was provisioned, no public execution enabled and no WORM setting changed. The overall goal remains incomplete.
