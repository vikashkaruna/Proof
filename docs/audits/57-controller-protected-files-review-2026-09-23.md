# Review 57 — protected controller file delivery

The real controller entrypoint now verifies protected files and exact workload identity, but there was no reviewed host delivery path for those files. This slice introduces fixed file inventory, tenant/node/image/file-hash review metadata, fresh preparation and root-only versioned installation. It does not start or enable the controller.

The host checks the currently installed SPIRE manifest and runner binding before writing, fixes container paths/launcher/volume/listener references and records the generation manifest before secret writes. Host ancestry is root-only; the bind-mountable child is root-owned 0755 and its files belong to controller UID/GID 20000 with mode0400. The intended readonly mount prevents chmod/write inside the container. Completed identical installs preserve files; incomplete or changed generations are refused without repair. A source-independent checker revalidates hashes, ancestry, ownership, mode, link count and completion receipt. Private bytes and arbitrary error details are not emitted.

The installer deliberately does not duplicate the complete TypeScript KMS/scheduler/TLS policy validator. Actual controller --check remains authoritative, after protected file delivery and before service activation. The manifest records the intended image, but loaded-image inspection and selector admission remain supervised-start obligations. Config receipt does not confer application approval. No cloud resources, roles, jobs or schema are changed.

Ten unit tests cover pre-write refusal, binding changes, durable ordering, idempotence, partial-generation preservation and file/path tampering. The local protected preparer passes and refuses output overwrite. A separate local Ubuntu Docker probe also passes actual root delivery against an installed SPIRE bundle, UID/GID 20000 and mode0400 verification, identical retry/check and tamper refusal. It exposed a capability-sensitive ordering issue: the installer now sets mode before transferring ownership. This probe does not run a live controller. Nine added native checks use the installed fixture runner manifest with real filesystem ownership and a read-only container: prepare-only, bound delivery, idempotence, exact-UID access, worker denial, tamper preservation, foreign node refusal, incomplete-generation preservation and source-independent checking. Native evidence remains pending until exact-merge CI. The fixture files are synthetic and are not presented as valid production TLS/backend credentials; node attestation remains local join-token.

Next implement ownership-bound supervised Docker lifecycle, private host-IP publishing, live runtime-volume checks in the host mount namespace, and the controller's 85-second shutdown window. Real private TLS/DNS, scoped cloud permissions, scheduler identity/delivery and GCP/backup acceptance remain open.
