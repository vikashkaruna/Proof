## Findings and implementation

- **The outbox had no production key provider.** AWS/GCP dispatch adapters now implement `DispatchKeyWrapper` with dedicated tenant key policy and regional endpoints. They are explicit controller dependencies; no browser route, worker credential or default activation was added. Trusted configuration fixes the permitted resources. Foreign tenants/keys, aliases, regions and arbitrary endpoints cannot be selected by an envelope.
- **Opaque bytes are insufficient authority for key selection.** The adapter parses and re-encodes the versioned dispatch context, validates every assignment field and rejects noncanonical or foreign-purpose contexts before any provider operation. AWS authenticated context and GCP AAD bind a purpose-separated digest of those bytes. This keeps full tenant/job metadata out of KMS audit context while preserving every assignment binding. Only a random data key reaches encryption calls; payload/proof remain in the controller.
- **Provider errors and integrity failures must not leak or release plaintext.** AWS key identity/algorithm and GCP version-prefix, verification flags and CRC32C checks are mandatory. Returned plaintext must be exactly the expected key length; strings must use canonical base64. Sizes are bounded before copying. SDK plaintext and temporary copies are cleared best-effort on success/refusal. Exceptions are fixed and contain no original cause or provider detail.
- **A timeout is not proof that a provider operation stopped.** The caller has a fixed budget, AWS receives an abort signal with one SDK attempt and GCP receives a deadline with retries disabled. The adapter remains occupied until the outstanding operation settles, preventing unbounded accumulation. Late plaintext is discarded and cleared. An uncertain outbox claim remains single-use and must be reconciled.
- **Removing an old primary can strand queued jobs.** `DispatchKeyPolicy` copies and freezes validated per-tenant rings. `withReadable()` stages a new reader key without changing the primary. `withPrimary()` promotes only an already-readable key while retaining every old reference; the original policy is untouched. No removal, disable or destroy operation exists. This is a rotation preparation primitive, not a distributed rollout fence. Reader-first configuration rollout and producer cutover remain explicit gates in Doc 16.

The provider behavior follows the primary [AWS Encrypt](https://docs.aws.amazon.com/kms/latest/APIReference/API_Encrypt.html), [AWS Decrypt](https://docs.aws.amazon.com/kms/latest/APIReference/API_Decrypt.html) and [encryption-context logging](https://docs.aws.amazon.com/kms/latest/developerguide/encrypt_context.html) references. Google's [regional endpoints](https://docs.cloud.google.com/kms/docs/reference/service-apis-overview), [encrypt integrity fields](https://docs.cloud.google.com/kms/docs/reference/rest/v1/projects.locations.keyRings.cryptoKeys/encrypt) and [decrypt integrity fields](https://docs.cloud.google.com/kms/docs/reference/rest/v1/projects.locations.keyRings.cryptoKeys/decrypt) inform the GCP adapter. Key-version rotation does not rewrite old ciphertext; retain required versions as described in Google's [re-encryption guidance](https://docs.cloud.google.com/kms/docs/re-encrypt-data).
