# Review 48 — exact SPIRE workload admission and separate host persistence

The next W4.3 deployment boundary requires workload identities tied to the reviewed runner and image. The existing local UID attestation and Docker launcher image availability checks do not establish that registration policy. The new offline renderer prepares GCP IIT server/node configurations and proposed entries binding the immutable project/instance node parent, UID and `docker:image_config_digest` for the controller and implemented assessment worker. It never enrolls, installs or mutates registrations. Unknown/duplicate manifest fields, malformed identities and unsafe image/address forms are refused. Output is owner-only and a reviewed directory is never overwritten.

The exact image selector matters: SPIRE's Docker `image_id` selector is an image name/tag, while `image_config_digest` identifies content. The policy adds no project-wide node alias, broad UID fallback, administrative workload or authority for unimplemented agents. The server's project allowlist still permits other project nodes to attest; it is the workload entry's exact parent that narrows workload authority. Build provenance, mount integrity, protected credentials and application task registration remain separate controls. See the pinned [Docker attestor](https://github.com/spiffe/spire/blob/v1.15.3/doc/plugin_agent_workloadattestor_docker.md) and [GCP node attestor](https://github.com/spiffe/spire/blob/v1.15.3/doc/plugin_server_nodeattestor_gcp_iit.md) contracts.

The new real local fixture runs the issuer and trusted node separately, with separate persistent state volumes, no public ports and no application credentials. It validates production configurations with checksum-pinned SPIRE 1.15.3, then explicitly substitutes local join-token attestation and a local node alias. SPIRE reserves `/spire/agent` for attestor identities, so a join-token alias cannot impersonate the generated GCP parent path. The fixture tests the same exact-parent selection semantics without claiming real Google attestation.

Positive probes and wrong-image/UID/parent refusals exercise the real Docker attestor. Issuer and node container recreation preserves registration/trust, recovers without another bootstrap token, and retains the image restriction. A separate empty node volume cannot recover workload authority during the bounded probe; restoring the original state recovers it. The node can retry enrollment rather than exiting immediately, so process exit is not the assertion. Issuer admin state and host PID/daemon access are separated. Probe processes have names and bounded lifetimes, and cleanup includes all containers/volumes. No identity tokens or raw diagnostics enter the result artifact.

**Confirmed open issue:** with the node still alive and issuer stopped, a cached workload identity remains available. This expected SPIRE behavior disproves treating local API availability as issuer synchronization readiness. The artifact records the demonstrated limitation, not a passed production health gate. Implement authenticated, bounded upstream synchronization evidence before activation; do not give the controller node administration merely to query health.
