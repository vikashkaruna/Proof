## Review findings and boundaries

The prior loader joined on control ID across all engagements and library versions, defaulted missing findings to 85, fabricated evidence identifiers from control IDs, treated zero exposure as absent and displayed invented fallback rows when any query failed. It also selected the first RLS-readable tenant's SDF setting. The UI repeated hardcoded domain outcomes. These were accidental deviations from evidence-backed assessment requirements.

The replacement never writes source records. It checks tenant ownership before reading dependent data, selects the exact library, verifies returned counts against both PostgREST totals and the published library declaration, and refuses duplicates or orphan findings. The existing numeric score bands are presentation only; finding lifecycle (open/closed/accepted risk) is not silently reinterpreted as a score. Historical assessments can be requested explicitly without borrowing current findings. Raw database/provider failures are not exposed.

Remaining worker execution is deliberately gated: the legacy Parikshan implementation still loads its default library and returns findings without persisting them. Passing the selected context from the page is necessary but is not evidence that execution uses/persists that version. Complete that behavior with the W4.3 scoped tool and regression gate; do not describe current invocation as a completed end-to-end assessment.
