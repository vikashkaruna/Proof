## Findings and implementation

- **In-memory rotation preparation did not fence old processes.** Migration 0047 persists reviewed per-tenant provider/key policy, canonical fingerprint, monotonic revision and publication receipt. Shared enqueue/claim locks and exclusive publication locks cover the previously absent-policy case and both race orderings.
- **A stale reader could consume a claim before discovering it could not decrypt.** SQL now checks its revision/fingerprint before claiming. Production wrappers derive fingerprints from their actual immutable local policy; dispatch captures revisions in a copied map. Durable startup recovery requires an exact local fingerprint match. Scheduler and worker protocols remain opaque and do not acquire policy authority.
- **Compatibility functions could bypass an optional wrapper.** The former implementations are renamed and execution is revoked from service/client roles. Managed tenants reject missing policy arguments. Unmanaged production resource references require explicit policy; preserved non-cloud legacy fixtures remain separate. Original actor/context checks still protect historical receipt recovery, which cannot create a new run or renew authority.
- **Rotation must not abandon retained data or reuse tenant resources.** Bootstrap accounts for historical outbox references even after payload purge. Updates cannot remove readable keys or change provider; primary promotion requires a previously staged reader. A global publication lock protects resource ownership across tenants, including competing initial reservations and historical jobs.
- **Publication needs conflict detection and audit atomicity.** The service-only publisher checks the authenticated owner's/admin's or internal founder's current membership. Compare-and-set revision detects stale updates. Ledger failure rolls back the policy/fence. Immediate lost-response retries recover the same receipt without a second event.
- **Line-ending references could pass JavaScript end-of-string regex checks.** Policy construction now explicitly rejects trimmed variants; SQL rejects whitespace. Fingerprint encoding uses canonical validated references and tenant/provider/primary context. Real integration proves SQL and TypeScript agree.
