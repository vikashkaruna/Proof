# Review 59 — tenant placement before controller activation

The dedicated-runner Terraform metadata was descriptive; the controller configuration could still be delivered to an unintended VM. This revision adds the preflight that the pending host supervisor must enforce. A reviewed profile names the tenant, protected file generation, private address and Mumbai zone. Installed files already bind the exact node, workload volumes, controller image and service configuration. The checker combines these bindings with actual fixed-path VM metadata and the active host interface, then reobserves the inputs before returning.

The metadata child uses Python's direct HTTP connection, never an ambient proxy or redirect. Only the custom tenant attribute, project ID, instance ID, zone and primary-interface private IP are read. Response size/ASCII/header checks and a separately enforced eight-second process deadline bound slow headers/body tricks; credentials and token endpoints are excluded. Google documents the [metadata endpoint and request header](https://docs.cloud.google.com/compute/docs/metadata/querying-metadata) and [instance metadata fields](https://docs.cloud.google.com/compute/docs/metadata/predefined-metadata-keys). This is trusted-host placement observation, not a replacement for SPIRE GCP IIT or authority against a compromised host/cloud administrator.

The controller file and placement helpers are now in the pinned host bundle and checked installed manifest. Existing differing installations are not overwritten. No startup/enable, Docker creation, resource provisioning, IAM grants, schema changes or application approvals are introduced. The function returns only reviewed nonsecret inputs; it does not persist an authorization receipt. Full activation still requires calling the preflight in the supervisor, actual image admission, private TLS, effective backend/secret/KMS scoping and scheduler authorization.

All 141 deployment tests pass, including 14 new placement tests. These exercise real local HTTP, strict paths/headers, proxy independence, redirect/oversize/binary/timeout denial, a trickling subprocess killed by the actual total deadline, foreign tenant/node/zone/address, duplicate or down interfaces and changing inputs. All 16 disposable Ubuntu host-delivery outcomes pass with the new helper inventory. Whole-revision CI is a separate gate. The local native SPIRE node uses join-token attestation and must remain unable to satisfy production GCP placement; no cloud claim follows from these fixtures.
