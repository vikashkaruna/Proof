# GCP preprod deployment: current gate

**Status (1 October 2026): blocked, no remote preprod deployment or acceptance recorded.** This replaces the older GCS vault/HMAC and mutable `:preprod` image instructions in this guide. Those instructions cannot satisfy [AGENTS.md](../AGENTS.md): the evidence vault must use AWS S3 Object Lock **Compliance** mode, with client personal data in `ap-south-1`. A GCS bucket can hold Terraform state, but it is not the evidence vault.

The GCP workload target is project `axiom-proof` (project number `188516662106`) in `asia-south1`; verify this identity again with the operator before applying anything. The preprod Terraform root provisions Cloud Run, Cloud SQL, service identities, Secret Manager and Artifact Registry. It consumes an **operator-owned AWS S3 bucket in ap-south-1** for evidence. Terraform does not create that bucket. The approved S3 provider must support native Object Lock Compliance, a seven-year default and exact-version retention readback. [The preflight](../scripts/verify-preprod-s3.py) uses scoped application credentials to read the bucket region, lock configuration, and a synthetic retained probe version before any cloud change. It rejects missing or non-Compliance proof.

The operator must provision and approve the S3 bucket, scoped credentials, a nonempty synthetic probe object/version retained in Compliance mode, and an access-controlled GCS Terraform-state bucket in `asia-south1`. State contains sensitive Terraform values; the deploy script refuses local state and initializes the regional GCS backend. Keep the private environment file and release manifest outside Git. Supply reviewed immutable upstream GoTrue and PostgREST digests. Fill every value in [the preprod environment template](../infra/docker/environments/.env.preprod.example), including `AXIOM_TF_STATE_BUCKET`, `AXIOM_RELEASE_SHA`, `AXIOM_RELEASE_MANIFEST_FILE`, `AXIOM_EVIDENCE_PROBE_KEY` and `AXIOM_EVIDENCE_PROBE_VERSION_ID`.

The exact release procedure, **only after the W8/W9/W10 engineering and security gates are green**, is:

1. Review the exact clean Git commit and its nine image sources. Set `AXIOM_RELEASE_SHA` to `git rev-parse HEAD`; the builder publishes `release-<SHA>` and writes a private manifest of nine registry digests. A reusable image tag does not identify a release.
2. Independently verify the S3 bucket/provider approval, default Compliance retention, probe version and regional state bucket. Execute `./scripts/deploy-preprod-gcp.sh --env-file <private-env-file> --dry-run` and review the full plan, project/region, secret inventory, image digest manifest and migration order. The script preflights S3 and state before any phase.
3. With the same clean commit and approved inputs, run `./scripts/deploy-preprod-gcp.sh --env-file <private-env-file>`. Do not invoke Terraform `apply` directly; that bypasses the live S3 check. Archive the exact commit, manifest, immutable deployed image digests, Terraform plan/state backend identity, migration ledger and Cloud Run service readbacks.
4. Use [the deployed acceptance runner](../scripts/run-deployed-acceptance.sh) with a **private target JSON**, first in `api-only` mode, then full browser mode. `./scripts/run-preprod-flow.sh <private-target-json>` is a compatibility wrapper that uses the same strict runner. There is no demo password or service-role fallback. Archive only allowlisted results; keep credentials and raw browser reports private.

If an approved S3 Compliance provider, synthetic probe, state backend, full image manifest, exact target identity, or acceptance credentials are missing, stop and record the blocker. Do not report the local Docker production profile as a remote deployment. [Doc 18](18_Operator_Deploy_And_Acceptance.md) defines the production promotion and live acceptance gates.
