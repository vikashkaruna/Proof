## 5. Operator deployment and acceptance steps

### Step 0 — Promotion (do first)

Open a PR from `origin/staging` into `main` (e.g. `git push origin origin/staging:refs/heads/promotion/rev98`), **merge commit only — never squash**, merge only when every check including the Security scan is green. Confirm `origin/main..origin/staging` is empty afterward.

### Step 1 — Secrets

Run `scripts/mint-supabase-keys.mjs` to generate fresh JWT/ANON/SERVICE keys and the approval signing key. Rotate in: the Supabase stack (JWT secrets), the BFF environment (`SUPABASE_SERVICE_KEY`, `APPROVAL_SIGNING_KEY`), and `infra/docker/environments/.env.preprod.example`. Never commit the new values; the old fingerprints stay ignored in `.gitleaksignore` as retired history.

### Step 2 — Database

1. Apply migrations against the target instance: `python3 scripts/migrate-database.py --dsn postgres://…` (TLS required by default; records checksums in `axiom_migrations`; refuses changed historical migrations).
2. Prove the schema: `./scripts/test-database.sh` spins a disposable Supabase Postgres 17 container, applies 0000–0071 fresh with `service_role nobypassrls`, runs every `tests/database/*.test.sql` and all 20 concurrency files plus the 13 populated-upgrade scripts.
3. **RDS staging acceptance (operator):** repeat 1–2 against the RDS staging instance over the network — this is the recorded W4.6 leftover that cannot be proven from local CI.

### Step 3 — Services

- **BFF** (`services/bff`): build + deploy the Hono app; health-check `/v1/monitoring/health`; confirm the new W8 routes respond and refusals return 409.
- **Agent runtime** (`services/agent-runtime`): deploy; **enable `feature_continuous_scheduler=true` per environment** to switch on the W6 scheduler loop (off by default). Watch `monitoring_schedules.next_run_at` advance and `drift_events` appear for `drift_check` schedules.
- **Temporal workers, model gateway**: deploy per `docs/08_DEPLOYMENT_GUIDE.md` / `docs/09_RUNBOOK.md`.
- **Helm charts**: the unused `SUPABASE_SERVICE_KEY` in the web and marketing charts is a recorded leftover — remove it during the next chart release.
